## Source and deployment

`live/sql/workspace.sql` is generated by `scripts/prepare-live.cjs`. Existing parts have already been applied; do not replay them blindly. `staging/sql/001`–`005` are for disposable NEW EMPTY test databases only; never execute that public-schema SQL against the shared environment.

Three isolated Edge Functions serve the workspace:

- `tracker-workspace-plan`: authenticates the caller and checks PM membership; uses the existing server-side AI credential. PDF/TXT upload analyzes automatically; JSON plan import is direct. Image-only PDFs still need OCR or manual text.
- `tracker-workspace-team`: resolves or invites accounts after an explicit PM action, then links professional contacts. Auth invitation/sign-in email is separate from receipt copies.
- `tracker-workspace-receipts`: authenticates the caller and verifies project ownership with caller JWT/RLS before service-level queue reads. Requires `RESEND_API_KEY` and a verified `WORKSPACE_RECEIPT_FROM` on the server. This provider configuration remains unavailable; the UI hides dispatch while download remains available.

Never place server/service credentials in the browser or repository. Recipient addresses come from the verified Auth identity stored transactionally with the signature, not browser-selected addresses. Dispatch is an explicit PM action. Provider acceptance is not inbox delivery. Idempotency protects retries within the provider window; jobs over 23 hours require reconciliation.
